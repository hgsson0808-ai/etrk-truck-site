# 매물 소개글 작성 지침

> {업체명} 과 {전화번호} 는 저장소의 brand.json 에 있는 name, phone 값으로 바꿔 읽습니다. 글에는 반드시 그 값 그대로 씁니다.

> 경로 안내: `$W` 는 작업 폴더(기본 /tmp/mt-intro), `저장소폴더` 는 사이트 저장소를 clone 한 폴더입니다.
> 차종 제한 없음: 수입차·대형·1톤 소형 특장차·18개 차종 밖 특장차 모두 정상적으로 씁니다.
> 사진이 거의 비었거나(0바이트), 판매 글과 사진이 명백히 다른 차이거나, 판매 글의 장비가 사진에 없으면 쓰지 말고 `저장소폴더/data/desc-hold/{id}.json` 에 {"hold": "이유", "photos": facts의 photos 배열 그대로} 를 남깁니다. prep.py 는 보류 매물의 사진이 바뀌면(새 사진이 올라오면) 자동으로 다시 고릅니다 — facts 에 "held_before": true 가 있으면 전에 보류했던 차이니 새 사진으로 쓰고, 소개글을 쓴 뒤 desc-hold 파일을 지웁니다(다시 보류하면 photos 를 새 목록으로 갱신).
> 보류 사유가 "상품화·구조변경 중"처럼 사장님이 알고 있는 경우는 보고에서 차량번호(facts의 plate)와 함께 한 줄로만 적습니다.
> 주행거리 km 보정은 계기판이 또렷하고, 앞자리 하나 빠진 걸로 설명되지 않을 때만 합니다.

{업체명}(중고 화물차·특장차 매매, 전화 {전화번호}) 홈페이지 매물 페이지에 들어갈 소개글을 쓴다.
형식은 트럭매매센터처럼 "사진 → 설명 → 사진 → 설명". 결과는 매물마다 JSON 파일 하나.

## 입력 (매물마다)
- `$W/facts-{id}.json` : 판매 정보(연식, 주행거리, 가격(만원), 변속기, 압류/저당, 판매자 글 desc 등)
- `$W/sheet-{id}.jpg` : 사진 전체를 번호(01~16) 붙여 한 장에 모은 시트. 먼저 이걸 본다.
- `$W/{id}/NN.jpg` : 개별 사진(1024×768). 명판·표기·계기판 글씨처럼 자세히 봐야 할 때만 연다.

## 출력
`저장소폴더/data/desc/{id}.json` (UTF-8, 아래 예시와 같은 키)

## 반드시 지킬 것 (가장 중요)
1. **지어내지 않는다.** 사진에 보이는 것, 판매 정보(facts)에 적힌 것, 검색으로 확인한 것만 쓴다. 차 상태가 "좋다/깨끗하다/관리 잘 됨" 같은 평가는 사진으로 분명히 보일 때만, 조심스럽게.
2. 사진에 단점(녹, 찍힘, 타이어 갈라짐, 오염)이 보이면 감추지 말고 사실대로 짧게 적는다.
3. 제원 수치(적재함 길이, 탑 크기, 파렛트, 마력 등)는 facts나 사진 속 표기에 있는 것만. 없으면 쓰지 않는다.
4. **장비차·특장차(크레인, 집게, 냉동기, 윙 장비, 리프트, 덤프 장비 등)에 모델명이 있으면** 그 장비 사진의 설명에 어떤 장비인지 함께 넣는다. 제조사 공식 자료를 WebSearch/WebFetch로 확인한 수치만 쓰고, 출처를 notes에 적는다. 확인 못 하면 수치 없이 "정확한 제원은 장비 명판 기준으로 안내해 드립니다"처럼 쓴다.
5. 사진 속 명판(장비 명판, 냉동기 표기 등)은 개별 사진을 열어 읽고, 읽은 그대로 쓴다.
6. facts와 사진이 다르면(예: 제조사/모델 배지, 톤수 표기, 연식) 본문은 사진 기준이 분명할 때만 사진을 따르고, **notes에 "확인 필요"로 반드시 적는다.**
7. facts의 maker가 비어 있는데 사진 배지(MIGHTY, MEGA, PAVISE, XCIENT, NOVUS, MAXEN, QUON 등)로 제조사·모델이 분명하면 JSON에 "maker", "model"을 넣는다(예: "현대", "메가트럭"). 불분명하면 넣지 않는다.
8. 사진에 차량번호판이 보여도 VIN(차대번호)은 쓰지 않는다. 사람 얼굴·개인정보는 언급하지 않는다.
9. 판매자가 넣은 홍보 문구 사진(글씨만 있는 안내 이미지 등)은 섹션에서 뺀다.
10. 상호는 항상 "{업체명}". 전화번호는 정확히 {전화번호}.

## 문체
- 손님(화물차 구매자)에게 딜러가 설명하는 존댓말. 짧고 담백하게. 과장·감탄사·이모지 금지.
- 섹션 text는 1~3문장. 사진에 실제로 보이는 것을 말하고, 구매자가 확인할 포인트를 한 줄 덧붙여도 좋다.

## JSON 구성
- "title": `{제조사} {모델} {톤}톤 {차종} 중고 {연식}년식 {핵심특징 1~2개}` (예: "현대 파비스 5톤 집게차 중고 2023년식 앞축 히아브 13500XG"). 쉼표 없이, 50자 안쪽. "중고화물차"를 끝에 붙이지 않는다.
- "headline": 화면 제목. `{제조사 모델 톤 차종} {연식}년식 · {핵심 3~4개 쉼표로}`
- "meta_description": 150자 안쪽 한두 문장, 연식·차종·핵심 사양·주행거리·압류저당
- "cover": 1
- "intro": 2~4문장 요약 (사실만)
- "sections": 사진 8~12개를 고른다. `{"photo": 사진번호, "heading": 짧은 제목, "text": 설명}`. 순서: 외관(전측면/정면/측면/후면) → 적재함·탑·장비 → 실내·계기판 → 하체·타이어. 비슷한 사진은 하나만.
- "outro": 2~3문장 마무리, 마지막에 "{업체명} {전화번호}"
- "faq": 4개. 이 차에 맞는 질문 2개(제원/장비 등, 답은 사실만) + 아래 2개 고정:
  - {"q": "압류나 저당이 있나요?", "a": "등록 정보 기준 압류 {seizure} · 저당 {mortgage}입니다. 계약 전 등록원부로 다시 확인해 드립니다."}
  - {"q": "명의이전 서류는 어떻게 하나요?", "a": "사고팔 때 필요한 명의이전 서류는 {업체명}이 챙겨 드립니다."}
- "notes": 내부 메모 배열 (확인 필요 사항, 장비 제원 출처). 손님에게 안 보임.
- "id": 매물번호

## 끝나면
각 JSON이 `python3 -c "import json;json.load(open(PATH))"`로 열리는지 확인하고, 매물별로 notes 요약을 한 줄씩 보고한다.

## 추가 지침 (사장님 확인 사항 반영)
- 사진 속 번호판이 facts의 plate와 달라도 **같은 차**로 본다. 매입 때 영업용 번호였다가 상사 이전하면서 일반 번호로 바뀐 경우가 많다. 본문에 번호판 번호는 쓰지 않는다. notes에도 적지 않아도 된다.
- 계기판 주행거리가 facts와 크게(1만km 이상) 다르면 **사진(계기판) 기준**으로 쓰고 JSON에 "km": 숫자 를 넣는다. notes에 원래 값과 함께 적는다. 작은 차이(수백km)는 촬영 시점 차이이므로 facts 값을 쓰고 무시한다.
- 사진상 차종이 facts의 type과 분명히 다르면(예: 카고로 등록됐는데 윙바디) JSON에 "type": "윙바디" 를 넣고 notes에 적는다. 차종 이름은 다음 중 하나: 카고, 윙바디, 냉동탑, 익스탑, 내장탑, 카고크레인, 집게차, 고소작업차, 바가지차, 덤프, 암롤, 셀프로더, 탱크로리, 살수차, 버큠로리, 압착진개차, 음식물수거차, 활어차
- 사진에서 수입 트럭(볼보, 스카니아, 만 MAN, 벤츠, 이베코, 다프, 이스즈, 후소)으로 확인되면 "maker"에 그 제조사를 넣는다(MAN은 "만(MAN)").
- 제목·본문에 "신차급", "A급", "최상" 같은 평가 단어를 쓰지 않는다.
- 가격이 9,999만원이면 임시 가격일 수 있으니 본문에 가격을 언급하지 않고 notes에 적는다.

## 네이버 검색 노출(SEO) 기준 — 반드시 적용
근거: 네이버 D.I.A. 문서 평가 요소(주제 적합도·경험 정보·정보 충실성·문서 의도·어뷰징·독창성·적시성), 서치어드바이저 콘텐츠 점검(제목·설명이 주제를 명확히), AI 브리핑 출처 원칙(결론 우선, 질문-답, 완결 문장).
1. **주제 적합도 — 한 페이지 = 이 차 한 대.** 다른 차·일반론으로 새지 않는다. 핵심 검색어 = `{톤}톤 {차종}` + `중고`/`매매`, 특장차는 장비명(예: "히아브 집게차", "호룡 스카이").
2. **title:** 이미 정해진 형식 `{제조사} {모델} {톤}톤 {차종} 중고 {연식}년식 {특징}`. 50자 안쪽, 쉼표 없음.
3. **meta_description:** `{연식}년식 {제조사 모델} {톤}톤 중고 {차종}`으로 시작 → 핵심 사양·주행거리·압류저당 → "{업체명} {전화번호}". 80~150자.
4. **결론 우선 intro(2~4문장):** 첫 문장에 이 차가 무엇인지(연식·제조사·모델·톤·차종·핵심 장비) 한 번에. 둘째 문장에 구매 판단 핵심(주행거리·변속기·적재함 치수/장비·압류저당). 가격이 9,999/7,777/1,234만원 같은 임시값이 아니면 가격도 넣는다.
5. **정보 충실성:** 확인되는 항목은 빠짐없이 — 연식·최초등록·주행·변속기·연료·톤수·적재함/탑 치수·장비 모델·옵션·압류저당·사진상 단점. 분량은 intro+섹션+outro+faq 답 합쳐 **1,000자 이상**이 목표(사실이 부족하면 억지로 채우지 않는다).
6. **경험 정보(사진 관찰):** 섹션마다 사진에서 직접 보이는 구체 디테일(명판 글씨, 계기판 숫자, 장비 표기, 녹·마모 위치)을 쓴다. "사진상 ~가 보입니다"처럼 관찰 근거를 드러낸다. 실차 점검을 한 것처럼 쓰지 않는다.
7. **완결 문장:** 문장 하나만 읽어도 뜻이 통하게. "이것", "해당 부분" 같은 지시어 위주 문장 금지. "항상/무조건/완벽" 같은 절대 표현 금지.
8. **질문-답 FAQ:** 앞 2개는 손님이 검색창에 칠 문장형 질문(예: "이 5톤 윙바디 적재함 길이는 얼마인가요?") + 첫 문장에서 바로 답. 뒤 2개(압류·저당, 명의이전) 고정.
9. **heading:** 짧고 구체적으로, 차종·부위·장비 단어 포함(예: "윙바디 적재함 내부", "히아브 13500XG 집게").
10. **어뷰징 금지:** 키워드는 전체 3~5회 자연스럽게. 같은 말 반복·나열·숨긴 키워드 금지.
11. **독창성:** 다른 매물과 같은 문장 복사 금지. outro도 매물마다 다르게.
12. **표기 일관:** 장비·제조사 이름을 글 전체에서 같은 표기로(예: 히아브/HIAB 혼용하지 말고 "히아브(HIAB)" 첫 회 후 "히아브").

## 추가 지침 2 (수정 작업에서 확인된 실수 방지)
- **운전석·조수석:** 국내 화물차는 운전석이 왼쪽이다. 사진에서 차 앞머리가 **왼쪽**을 향하면 보이는 면은 **운전석 쪽**, 앞머리가 **오른쪽**을 향하면 **조수석 쪽**이다. 옆문·리프트·연료탱크 위치도 이 기준으로 사진에서 직접 확인하고 쓴다.
- **홍보 문구가 박힌 사진**(판매자 글씨·"상품화중"·"도색중"·"AI로 생성한 콘텐츠" 표시)은 섹션에 쓰지 말고, 같은 장면의 깨끗한 사진을 쓴다. "cover"도 깨끗한 외관 사진 번호로 정한다.
- **차량 명판(차대번호 보이는 사진)**은 섹션에 쓰지 않는다. 명판의 제작연월·총중량 등은 글로만 옮겨도 된다.
- **사진 번호**는 시트에 있는 번호만 쓴다. 같은 사진을 두 번 쓰지 않는다.
- **FAQ는 정확히 4개**, 마지막 2개는 압류·저당 / 명의이전 고정.
- **프리마:** 사진으로 원쓰리·투쓰리(대형 캡 + 다축 대형)면 "body": "L", 그 외 중형 바디(증톤·가변축 포함)면 "body": "5"를 JSON에 넣는다.
- JSON에 "remote": true 를 넣는다(원본 사진 순서 기준이라는 표시).
