구글·네이버는 같은 글이 3곳에 있으면 복사한 글로 보고 한 곳만 보여 주기 때문입니다.

## 반드시 지킬 것
1. **사실은 셋 다 같다.** 연식·주행·가격·치수·장비명·단점은 같은 자료(facts·사진)에서 나오므로 같아야 한다. 다른 것은 문장·순서·강조점·검색어뿐이다.
2. **문장 복사 금지.** 한 사이트 글의 문장을 다른 사이트에 그대로 또는 단어 몇 개만 바꿔 쓰지 않는다. 섹션마다 다른 사진을 골라도 좋다(같은 장면 사진이 여러 장이면 사이트마다 다른 번호를 고른다).
3. **업체명·전화는 그 사이트 brand.json 값만.** 다른 사이트 이름이 섞이면 안 된다(check.py 가 전화번호는 잡지만 업체명은 직접 확인).
4. **보류(hold)는 셋 다 같이.** 한 사이트에서 보류한 매물은 같은 이유로 다른 두 곳에도 data/desc-hold/{id}.json 을 만든다. 같은 차이기 때문이다.
5. **사진이 2장 이하인 매물**은 셋 다 쓰지 않는다(prep.py 기준). 사진이 늘어나면 다음 작업 때 자동으로 잡힌다.
6. brand.json·템플릿·build.py 는 건드리지 않는다. 소개글 파일(data/desc, data/desc-hold)만 만든다.

## 작업 재료
- 사진·사진시트·facts 는 각 저장소의 `intro-work` 브랜치에 GitHub이 준비해 둔다(각 저장소 `.github/workflows/intro-prep.yml`).
- 저장소에 `intro/` 폴더나 `intro-prep.yml` 이 없으면 daesung-truck-site 의 것을 그대로 복사해 넣는다(prep.py·check.py 는 그 저장소 config/brand.json 값을 자동으로 읽는다).
- 사진은 세 사이트가 똑같으므로, 어느 한 저장소의 intro-work 재료로 세 사이트 글을 다 써도 된다. 단 매물번호 목록은 **사이트마다** data/desc·desc-hold 를 따로 빼고 계산한다.
