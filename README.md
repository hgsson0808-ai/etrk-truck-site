# 중고화물차 광고 홈페이지 만들기 묶음

카매니저로 운영하는 업체 홈페이지(예: 대성트럭 www.대성트럭.com)에서 매물을 자동으로 가져와 만드는 **광고용 홈페이지**를 그대로 따라 만드는 묶음입니다.
미래트럭(miraetruck.co.kr)에서 쓰는 것과 같은 프로그램입니다.

## 완성되면 이렇게 돌아갑니다

| 언제 | 누가 | 하는 일 |
|---|---|---|
| 매시 정각 | GitHub (무료, 클로드 사용량 안 씀) | 카매니저 홈페이지 매물을 확인해 새 차 올리기, 판매된 차 내리기, 가격 바뀐 것 고치기 → 홈페이지 자동 반영 |
| 매일 새벽 3시 | GitHub | 매물 전체를 처음부터 다시 확인 |
| 매시 30분 | 클로드 예약 작업 | 소개글 없는 새 매물을 사진 보고 네이버 검색용 소개글 작성 → 다음 정각에 홈페이지 반영 |

홈페이지 구성: 첫 화면(큰 사진 5장·차종 바로찾기·최근 매물), 내차사기(차종 선택), 차종별 페이지(톤수 + 변속기·제조사·주행거리·연식 고르기), 매물 상세(사진 넘기기·사진 슬라이드 영상·소개글·성능기록부·알선판매 ? 판매상사), 내차팔기 문의.

## 업체마다 바꾸는 것 = `brand.json` 파일 하나

| 항목 | 뜻 |
|---|---|
| `name` | 업체 이름 (홈페이지·소개글 전체에 들어감) |
| `phone` | 대표 전화번호 (`010-0000-0000` 모양) |
| `colors.main` / `colors.dark` | 홈페이지 색. main = 메뉴·버튼 색, dark = 진한 글씨 색 |
| `source_site` | 매물을 가져올 카매니저 홈페이지 주소 |
| `domain` | 새로 살 홈페이지 주소 (예: `https://대성트럭.kr`) |
| `img_host` | 사진 중계 주소 (예: `https://img.대성트럭.kr`) |
| `dealer`, `biz` | 광고 의무 표시(종사원·소속 상사·사업자 정보) — **반드시 실제 값** |
| `hours`, `promises`, `tagline` | 영업시간·약속 4가지·한 줄 소개 |

- 이름·전화번호·가져올 홈페이지는 대성트럭 값으로 미리 넣어 두었습니다. 맞는지 확인하세요.
- 로고: `data/brand/logo.png` 에 로고 그림(투명 배경 PNG)을 넣으세요. 없으면 업체 이름 글자로 자동으로 만듭니다.
- 첫 화면 큰 사진: `data/hero/1.jpg ~ 5.jpg` 를 넣으면 그 사진, 없으면 최근 매물 사진이 자동으로 들어갑니다.
- 첫 화면 문구(`templates/home.html` 맨 위 slides)에 "명의이전·서류까지 한 번에" 같은 약속이 있습니다. **우리 업체가 실제로 하는 일만** 남기고 고치세요(광고는 사실만).

## 준비물 (전부 무료로 시작 가능)

1. **GitHub 계정** — 프로그램과 홈페이지 파일을 보관 (비공개 저장소)
2. **Cloudflare 계정** — 홈페이지 올리기(Pages) + 사진 중계(Workers)
3. **도메인** — 홈페이지 주소 (Cloudflare에서 사거나, 산 도메인을 Cloudflare로 연결)
4. **클로드** — 이 묶음을 들고 클로드에게 아래 첫 메시지를 주면 같이 만들어 줍니다

로그인·결제·인증(문자, 이메일 확인)은 클로드가 대신하지 않습니다. 그 단계가 나오면 직접 하세요.

## 클로드에게 처음 보낼 메시지 (그대로 복사)

```
첨부한 truck-site-kit.zip 은 카매니저 홈페이지 매물로 광고용 홈페이지를 만드는 프로그램 묶음이야.
README.md 를 끝까지 읽고 순서대로 같이 만들어 줘.
- 업체: 대성트럭, 매물 가져올 곳: https://www.xn--vk1bl7gk9i2is.com (www.대성트럭.com)
- brand.json 의 이름·전화번호·색상만 우리 걸로 바꾸고 나머지는 그대로 쓸 거야.
- 로그인이나 인증이 필요한 단계는 나한테 하라고 알려 줘.
```

## 만드는 순서 (클로드가 따라갈 순서)

1. **brand.json 채우기** — 이름, 전화번호, 색(main/dark), dealer·biz 실제 값. 색은 업체 로고·기존 홈페이지 색을 보고 정합니다.
2. **시험 만들기**
   ```
   pip install -r requirements.txt
   python3 sync.py --limit 40      # 매물 40대만 가져와 시험 (전체는 python3 sync.py, 5~8분)
   python3 build.py site           # dist/site/ 에 홈페이지가 만들어짐
   cd dist/site && python3 -m http.server 8000   # 브라우저로 http://localhost:8000 확인
   ```
   - 카매니저 홈페이지가 인증서 중간 단계를 안 보내서 `certs/` 의 중간 인증서를 같이 씁니다. **인증서 검사를 끄면 안 됩니다.**
3. **사진 중계(Cloudflare Worker) 올리기** — `img-worker/`. `wrangler.toml` 의 routes 를 `img.내도메인` 으로 바꾸고 `npx wrangler deploy` (또는 Cloudflare 화면에서 Workers → GitHub 연결). brand.json `img_host` 와 같은 주소여야 합니다.
4. **GitHub 비공개 저장소 만들고 올리기** — 이 폴더 전체를 올립니다. 전체 매물로 한 번 `bash daily.sh` 를 돌리면 `site/` 폴더가 생기고 올라갑니다.
5. **Cloudflare Pages 연결** — Pages → GitHub 저장소 연결, 빌드 명령 없음, 출력 폴더 `site`. 도메인 연결.
6. **매시간 자동 갱신 켜기** — `.github/workflows/hourly.yml` 이 이미 들어 있습니다. GitHub 저장소 → Settings → Actions → General → Workflow permissions 를 **Read and write** 로. Actions 탭에서 "매물 매시간 갱신" → Run workflow 로 한 번 시험.
   - 비공개 저장소 무료 실행 시간은 한 달 2,000분. 매시간은 바뀐 매물만 확인해 1~2분이라 충분합니다.
7. **소개글 쓰기**
   - 처음 한 번: 소개글 없는 매물이 수백 대라 클로드에게 "intro/prep.py 로 100대씩 나눠 소개글 써 줘" 하고 여러 번 나눠 씁니다. 지침은 `intro/BRIEF.md`, 검사는 `python3 intro/check.py 매물번호,...`.
   - 그 뒤: 아래 예약 작업을 걸어 두면 매시 30분에 새 매물만 씁니다.
8. **네이버·구글 등록** — 서치어드바이저 / 서치콘솔에 사이트 등록, 사이트맵 `https://내도메인/sitemap.xml` 제출 (소유 확인은 직접).

### 매시 30분 소개글 예약 작업 (클로드 예약 작업으로 걸 내용)

시간: 매시 30분 (한국시간). 내용:
```
광고용 홈페이지에 새로 올라온 매물의 소개글을 쓰는 매시간 작업입니다. 매물 목록 갱신은 GitHub이 매시 정각에 따로 합니다.
1. GitHub 저장소 (내 계정)/(저장소 이름) 을 push 권한으로 붙이고 clone (이미 있으면 git pull --rebase).
2. 저장소 폴더에서 python3 intro/prep.py 20 실행. 마지막 줄이 NONE 이면 "새 매물 없음"만 남기고 끝.
3. 매물이 있으면 intro/BRIEF.md 를 끝까지 읽고 그대로 따름. 작업 폴더 /tmp/mt-intro. 6대 이상이면 5대씩 나눠 에이전트에게 동시에(각자 BRIEF.md 먼저 읽게).
   결과는 data/desc/{매물번호}.json, 쓰지 않을 매물은 data/desc-hold/{매물번호}.json 에 {"hold": "이유"}.
   사실만 씀. 업체명·전화번호는 brand.json 값만.
4. python3 intro/check.py 쓴매물번호,... 실행해 문제 고치기.
5. data/desc, data/desc-hold 새 파일만 커밋해서 main 에 push (git pull --rebase 후). 메시지 "새 매물 소개글 N대".
6. 인증서 검사 끄지 말 것. 다른 곳에 글 올리지 말 것.
7. 한국어로 짧게 보고: 쓴 대수, 보류 매물과 이유, 확인 필요한 점.
```

## 정해 둔 기준 (미래트럭과 똑같이)

- **전부 취급**: 수입차, 대형, 1톤 소형 특장차, 18개 차종 밖 특장차까지 모두 올림 (`config.py` 의 `is_handled`).
- **톤수는 바디 기준**: 1톤 / 2.5톤 / 3.5톤 / 4.5~5톤 / 5톤 이상. 증톤 중형(예: 파비스 7.5톤)은 4.5~5톤, 원쓰리·투쓰리 대형만 5톤 이상. 프리마는 사진 보고 판단(`data/body.json` 에 `{"매물번호": "5" 또는 "L"}`).
- **소개글**: 사진 → 글 → 사진 → 글. 네이버 검색 기준(제목 형식, 1,000자 이상, 질문형 FAQ 4개). 사진·판매 정보에 없는 건 쓰지 않음. 판매 글과 사진이 다른 차, 사진이 깨진 차는 보류.
- **카매니저 목록 주의**: 공개 목록 기본값은 중대형화물만 보여서, 소형화물(AAK)·버스(AAF) 목록도 따로 가져오게 되어 있습니다(`scrape.py`). 그래도 관리자 화면 "광고대수"와 몇 대 차이 날 수 있습니다(공개 안 된 차).

## 폴더 안내

| 파일·폴더 | 하는 일 |
|---|---|
| `brand.json` | 업체 정보 (여기만 바꿈) |
| `scrape.py`, `sync.py` | 카매니저 매물 가져오기 → `data/all_raw.json` |
| `build.py`, `templates/` | 홈페이지 만들기 → `dist/site/` |
| `daily.sh` | 가져오기 + 만들기 + GitHub에 올리기 한 번에 |
| `.github/workflows/hourly.yml` | 매시간 자동 실행 |
| `intro/` | 소개글 지침(BRIEF.md)·준비(prep.py)·검사(check.py) |
| `data/desc/` | 소개글 (매물번호.json) |
| `img-worker/` | 사진 중계 (Cloudflare Worker) |
| `certs/` | 카매니저 접속용 중간 인증서 |
